TWO REMAINING STEPS (console only)
  1. Firebase console > Build > Firestore Database > Create database.
     (Skip if it already exists — a locked-mode DB already answers with

  2. Firebase console > Firestore > Rules: replace everything with the
     contents of firestore.rules (ships next to this file) and Publish.
     These rules let each signed-in player create exactly one ballot per
     round, let anyone read the tallies, and let the poll doc be created

SEEDING THE CLOUD COPY OF THE TEST POLL (optional but recommended)
  With the rules published, say the word and I will create the
  polls/current document remotely in one call (the rules now allow exactly
  one create on it: question "test", options Yes/No/Maybe/IDK, active true,
  updatedAt "t2026-11-13a" -> vote round "ft2026-11-13a").
  You can also create it yourself in 60 seconds:
    Firebase console > Firestore > Start collection:  polls
      > Document ID:  current
      > fields:
          question  (string)         test
          options   (array)          ["Yes", "No", "Maybe", "IDK"]
          active    (boolean)        true
          updatedAt (number/string)  1
  Until the doc exists, the built-in default (identical test poll) is used.

ASKING YOUR OWN QUESTIONS (the fun part)
  To change the question at any time - no redeploy, no code edit - edit the
  polls/current doc in the console (console edits bypass the rules):
  change question/options, and bump updatedAt to start a NEW round.
  Everyone is asked again; old votes stay in voters but only the current
  round is tallied. To also change the built-in fallback, edit DEFAULT_POLL
  in games.html and re-upload.

SEEING / MANAGING RESULTS
  - Live: the Votes chip (visitors see it too).
  - Raw ballots: Firestore > polls > current > voters - one doc per vote,
    id <uid>__<round>, field choice = the option index (0 = first option).
  - Reset a poll: delete the docs inside voters (or just bump updatedAt).

BEHAVIOR / SAFETY DETAILS
  - One ballot per player per round: ballot docs are keyed by the player's
    anonymous UID + round, and the security rules only let that same player
    create the ballot or move its choice field. Re-confirmation in a later
    session MOVES the vote - tallies never double-count. Clearing browser
    storage gives a new anonymous UID (not tamper-proof, but stops casual
    abuse).
  - If Firebase is unreachable, sign-in fails, or a vote write is rejected,
    the page automatically falls back to counting that vote locally and
    ALWAYS unlocks the games - the gate can never permanently trap someone.
  - The gate also appears once per session even if the visitor never clicks a
    game (that is the "once per session" rule you picked).
  - Authorized domains: yoursite.web.app / .firebaseapp.com are allowed for
    sign-in by default. If you serve games.html from any OTHER domain, add it
    in Authentication > Settings > Authorized domains, or anonymous sign-in
    fails there (the page then auto-falls back to local mode - the gate
    still works, counts just stay per-browser).
  - Works inside FATE.html's games module too IF you rebuild the single-file
    bundle (scripts/build_fate_single.py) after editing games.html. The
    standalone multi-file site just needs the new games.html uploaded.
