FATE BROWSER — NOW 100% WISP (jet engine removed)
===================================================
b.html no longer uses the jet/scramjet files at all. It browses straight
over wisp: a lane sweep (binary handshake) picks the fastest live relay,
then a small service worker serves proxied pages through the libcurl
tunnel. Pages load from  <your-site>/e/<encoded-url>.

NEW FILES THAT MUST SHIP NEXT TO b.html
  wisp-sw.js            the proxy service worker (required)
  curl/index.plain.js   the libcurl/wisp client bundle, 2.1 MB (required;
                        the WASM is embedded inside it — no extra files)
  wisp-scanner.html     endpoint scanner (optional, feeds the browser)

HOW LANES ARE CHOSEN
  1. lanes the wisp scanner verified alive (localStorage fate_wisp_results)
  2. the last lane that worked (fate_wisp_lane_v6)
  3. 51 baked relays harvested from dozens of proxy repos on GitHub
  Top 6 fastest get tried until one starts the tunnel. Rescan any time
  from the lane card on the start page; the chip in the nav shows the
  live lane + ping.

BEHAVIOR NOTES
  - Works best on server-rendered sites (Wikipedia, news, docs, search,
    forums). Very heavy JS apps (Discord/Roblox-class) are better through
    the portal engine — same caveat as before.
  - Cookies are kept in a small per-host jar inside the worker (logins
    partially work; not a full cookie engine).
  - The old jet files (jet.*.js, sj/, fate-sw.js) can stay on the server —
    they are simply unused by b.html now.
  - Tested end-to-end on 2026-11-05 through a local relay: lane sweep,
    tunnel boot, example.com, full-styling Wikipedia (CSS/JS/images),
    in-tunnel link clicks, tabs, tiles, recents, rescan.

FATE OS — SINGLE-FILE BUILD (stormOS style)
===========================================
  FATE.html      the ENTIRE site packed into ONE file (~15.3 MB as of
                 2026-11-08, was ~22 MB): portal, games (10k vault inlined),
                 apps, live TV, watch, music, settings, the browser shell,
                 the relay scanner AND the 16.7 MB gn-math engine — the
                 engine is stored gzip+base64 (10.3 MB) and inflated in the
                 browser with DecompressionStream on first use (Chrome 80+ /
                 Safari 16.4+; the vault decoder already required the same
                 API, so no device that runs the vault can fail here). The
                 decode path detects the gzip magic bytes, so an older raw
                 base64 build still loads.

  How it works: a FATE OS shell (boot splash -> password gate -> dock)
  mounts every old page as a same-origin blob: URL iframe. Links between
  pages are intercepted and routed by the shell, so the old multi-page
  navigation just works. Apps keep running when you switch dock icons
  (the browser keeps its engine session).

  - Same password gate as before (fate_v6_auth, default 'fate2026').
  - Deep links still work: FATE.html#open=<encoded url> opens the browser
    on that page; FATE.html#games / #tv / #apps jump to a module.
  - Serve over http(s) (your local server app) — don't rely on file://,
    blob iframes and localStorage need a real origin.
  - The old multi-file site (index.html, b.html, gn-math.html, ...) still
    works standalone; FATE.html is the portable all-in-one edition.
  - Rebuild it any time: scripts/build_fate_single.py
